In the current project, run the read-only checks first and change nothing: `dev task reconcile` (doing items without a lock, open items of merged branches, items that share a title), `dev doctor` (read only its "work state" row: stale items and runs), `dev ci watches` (watches that expired while their run goes on), and `dev branch prune` without `--apply` (merged branches and their worktrees). Report the drift in one short table under the status block: each stale record, the evidence, and the fix its check prints; a clean check gets one line, "nothing stale." Then ask the developer which fixes to apply, and apply only those: `dev task reconcile --apply`, `dev branch prune --apply` (it deletes on origin, an irreversible action: the guard's gate needs the developer's grant, and a crew member never runs it), the re-arm command `dev ci watches` prints, and `dev task cancel <n> --why "duplicate of <id>"` for a duplicate. A stale run belongs to its own session: name it with its fix (`dev progress done "<outcome>"` there, or `dev session carry` after `/clear`) and leave it. Run the read-only checks again after the fixes and show what is left. Follow the `work-state` skill. $ARGUMENTS
