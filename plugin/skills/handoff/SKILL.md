# Handoff note

Every project has one note: `~/Development/.handoff/projects/<owner>/<repo>.md` (local projects:
`projects/_local/<name>.md`). The session-start context names the exact path. `dev handoff --path` prints it.

## Structure (keep it)

- `<!-- dev:auto:start --> … <!-- dev:auto:end -->`—generated by devkit: the path, the remote, the main checkout,
  and the branch map, one line per local branch with where it lives (local only, or local and origin), how far it is
  ahead and behind, whether its work is backed up (or why not), an embargo, its worktree and PR, and the project's
  backup policy. **Never edit inside it.**
- `## Purpose`—what the project is, who uses it, where it runs. 1–3 lines. Fill it once, fix it when wrong.
- `## Current state`—what works, what is half done, what is broken, right now. Rewrite; do not append history.
- `## Tasks`—generated from the work items. Change tasks with `dev task` (add, start, done, move, edit with
  `--why`), never by editing this block.
- `## Decisions and gotchas`—non-obvious facts: why X was chosen, traps, flaky tests, env quirks, credentials
  _location_ (never secret values).
- `## Session log`—newest first, one line per session. devkit adds the branch and commit list automatically
  (lines ending in `<!-- s:… -->`); you add one human summary line.

## Procedure

1. Read the note (and the auto block for branch/PR facts).
2. Check reality: `git status`, `git log --oneline -10`, open PRs (`gh pr list --author @me`), failing tests if any,
   and `dev branch ls`: a branch whose work exists only on this Mac gets `dev backup`, or an embargo with its reason
   (`dev branch embargo <branch> --why "…"`), or a line in Current state that says why it stays local.
3. Make the Tasks block true before you write around it: close each item you verified
   (`dev task done <id> --why "<evidence>"`), release the ones you stop (`dev task release <id>`), then run
   `dev task reconcile` and apply what it lists (`--apply` for lockless doing items and items of merged branches;
   `dev task cancel <id> --why "duplicate of <other id>"` for a duplicate). The `work-state` skill has the rest.
4. Edit Current state and Decisions and gotchas in place. Short sentences, concrete file paths and commands, no
   filler.
5. Add your one-line summary: `dev handoff --log "<outcome; what is next>" --agent <claude|codex>` (it goes to the
   append-only session log with your user, machine and agent). devkit adds the branch, commits, and your status block.
6. If plans or specs were written, link them (`~/Development/.handoff/plans/<owner>/<repo>/<file>.md`).
7. Do not commit or push the handoff repo yourself: `dev sync` (automatic at session end and hourly) does it.

## Rules

- Never put secrets, tokens, customer data, or personal data in the note.
- Keep the whole note under ~150 lines; move long material into `plans/` and link it.
- If the note contradicts the code, the code wins: fix the note.
