# Agents

devkit configures Claude Code and Codex from the same sources, so both follow the same instructions, use the same
skills, and are checked by the same hooks.

| Surface | Reads | Configured by |
|---|---|---|
| Claude Code CLI | `~/.claude/` | `dev install --only claude,instructions,skills` |
| Claude Desktop, Code tab (local sessions) | the same `~/.claude/` files | same as above |
| Codex CLI | `~/.codex/`, `~/.agents/skills/` | `dev install --only codex,instructions,skills` |
| Codex in the ChatGPT desktop app | the same `~/.codex/` files | same as above |

Claude Desktop SSH or cloud sessions and Codex cloud tasks run elsewhere and do not load this local
configuration.

## Global instructions

`agents/AGENTS.md` (plus your optional `~/.config/devkit/AGENTS.personal.md`) is rendered into two identical files:

- `~/.claude/CLAUDE.md` — loaded by Claude Code in every session;
- `~/.codex/AGENTS.md` — loaded by Codex in every session, before the repository's own AGENTS.md.

Each starts with a header such as:

```html
<!-- generated by devkit 1.0.0 from ~/Development/ancongui/devkit/agents/AGENTS.md; edit those and run `dev install` -->
```

The instructions cover: the instruction canary (section 0), the workspace layout, how to start a task, the working
method, files and disk, worktrees, git and GitHub (no AI attribution), local-first delivery, backend methodology,
skills and tools, stack conventions, handoff duty and the guard. A repository's own AGENTS.md / CLAUDE.md adds to
them; an explicit request from the user wins over both.

## Claude Code

### Settings (`~/.claude/settings.json`)

`dev install` merges these keys into your existing settings; keys it does not manage are left alone.

| Key | Value | Effect |
|---|---|---|
| `permissions.defaultMode` | `bypassPermissions` | No permission prompts; the guard and deny rules still apply |
| `skipDangerousModePermissionPrompt` | `true` | Skips the one-time confirmation of bypass mode |
| `attribution.commit` / `attribution.pr` | `""` | No Co-Authored-By trailer, no "Generated with Claude Code" line |
| `cleanupPeriodDays` | `14` | Transcripts and other per-session data older than 14 days are deleted by Claude Code |
| `env` | see below | Environment for every session |
| `hooks` | see [Hooks](#hooks) | devkit's hook handlers (any other handlers are kept) |
| `enabledPlugins` | the plugins in `config/claude/plugins.json` set to `true` | Plugins enabled everywhere |

`env`: `DOCKER_HOST=unix://~/.colima/default/docker.sock`,
`TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE=/var/run/docker.sock`, `NG_CLI_ANALYTICS=false`,
`NEXT_TELEMETRY_DISABLED=1`, `SUPERPOWERS_DISABLE_TELEMETRY=1`, and for the security-guidance plugin
`ENABLE_STOP_REVIEW=0` and `ENABLE_COMMIT_REVIEW=0`.

### Plugins and MCP servers

Plugins are installed from the `claude-plugins-official` marketplace at user scope; MCP servers are added with
`claude mcp add -s user` (replaced on each install so their arguments stay current). The list and the reasons are in
[Skills and plugins](skills-and-plugins.md).

## Codex

### Settings (`~/.codex/config.toml`)

devkit does not edit `config.toml` as text. It starts `codex app-server` and writes through Codex's own
`config/batchWrite` API, so Codex validates the values and keeps the file in its own format.

| Key | Value | Effect |
|---|---|---|
| `approval_policy` | `never` | No approval prompts (the equivalent of Claude's bypass mode) |
| `sandbox_mode` | `danger-full-access` | No sandbox; the guard is the safety net |
| `projects."<path>".trust_level` | `trusted` | For the dev root and every repository found under it (and new ones from `dev clone`, `dev new`, `dev adopt`) |
| `shell_environment_policy.set` | Docker, Testcontainers and telemetry variables | Environment for commands Codex runs |
| `mcp_servers` | from `config/codex/plugins.json` | context7, Chrome DevTools, Angular CLI |
| `hooks.state."<key>".trusted_hash` | hashes reported by Codex | Trust for devkit's hooks |

### Hook trust

Codex skips user hooks until they are reviewed. `dev install` writes `~/.codex/hooks.json`, asks Codex for the hooks
it sees (`hooks/list`, which returns each hook's key, current hash and trust status), and records trust for the
hooks declared in that file through `config/batchWrite`. When devkit's hooks change, the next `dev install` trusts
the new version. `dev doctor` shows each hook's trust status.

### Plugins

`codex plugin add` installs `superpowers@openai-curated-remote` and `impeccable@openai-curated-remote` (see
[Skills and plugins](skills-and-plugins.md)).

## Skills

Third-party skills are fetched from their upstream repositories at the pinned commits in `config/skills.json` into
`~/.local/share/devkit/skills/<name>` (each with a `.devkit-source` file naming repository, commit and licence).
They and devkit's own skills in `agents/skills/` are symlinked into:

- `~/.claude/skills/<name>` (Claude Code);
- `~/.agents/skills/<name>` (Codex).

Existing folders with the same name that devkit did not create are left untouched and reported.

## Hooks

Every hook calls the same entry point, `<devkit>/bin/dev hook <event> --agent claude|codex`, by absolute path, so
it works from the Desktop and ChatGPT apps whose PATH is minimal.

| Event | Claude Code | Codex | What it does |
|---|---|---|---|
| SessionStart | all sources, timeout 30 s | `startup\|resume\|clear\|compact`, timeout 30 s | Records the session's starting commit and branch; refreshes the project's auto block; clones `node_modules` copy-on-write into a fresh worktree; prints the workspace context (Claude: plain text; Codex: `additionalContext` JSON) |
| PreToolUse | `Bash\|Write\|Edit\|MultiEdit\|NotebookEdit`, timeout 15 s | `^(Bash\|apply_patch)$`, timeout 15 s | The [guard](guard.md): allow silently, or return `permissionDecision` `deny` / `ask` (Claude) or `deny` (Codex) with the reason |
| Stop | timeout 10 s | timeout 10 s | Instruction canary check (Claude shows a `systemMessage` warning when the marker is missing); at most every 10 minutes per session, a background `dev sync` that updates the session line |
| SessionEnd | timeout 10 s | timeout 3 s | Background `dev sync` that writes the session's final line and closes the session record |

The session context names the project and stack, the checkout (main or worktree) and its state and PR, detected
commands (`npm run …`, `./mvnw verify`, `uv run pytest`, `composer …`, `make …`), other worktrees and live sessions,
layout problems, and the handoff note.

**Fail-open.** Every handler catches all errors, logs them and exits 0 without output, so a devkit bug never blocks
or breaks a session. Background work is detached so hooks return in milliseconds.

**Logs.** `~/.local/state/devkit/logs/hooks.log` (errors and every guard decision), `~/.local/state/devkit/logs/sync.log`
(background syncs).
