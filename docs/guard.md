# Guard rules

The guard is the PreToolUse hook shared by Claude Code and Codex (`lib/devkit/guard.py`). Both agents run without
permission prompts, so the guard is the safety net for workspace rules. It is not a security boundary: it stops the
accidents that waste time and disk, and every denial tells the agent the right way, so it corrects itself in one
step.

It inspects:

- **Claude Code:** `Bash` (`command`), `Write`, `Edit`, `MultiEdit` (`file_path`), `NotebookEdit` (`notebook_path`);
- **Codex:** `Bash` (`command`) and `apply_patch` (the patch's `Add File`, `Update File` and `Move to` paths).

Shell commands are tokenised: chains (`&&`, `||`, `;`, `|`, new lines) are checked one by one, `cd`/`pushd` changes
the directory used to resolve later paths, leading `VAR=value`, `sudo`, `env`, `command`, `nohup`, `time`, `exec`,
`nice`, `caffeinate` prefixes are skipped, and output redirections (`>`, `>>`) are checked as writes.

## Decisions

| Decision | Claude Code | Codex |
|---|---|---|
| allow | no output | no output |
| ask | the user is asked to confirm (used only for writes outside the workspace) | not supported by Codex: becomes deny |
| deny | the tool call is blocked; the reason goes to the agent | the same |

## Rules

### File writes (Write/Edit/apply_patch, and `>` redirections)

| Path | Decision |
|---|---|
| Temp: `/tmp`, `/private/tmp`, `/var/folders`, `$TMPDIR`, `$CLAUDE_CODE_TMPDIR`, `~/Development/.tmp` | allow |
| Agent and tool config: `~/.claude`, `~/.codex`, `~/.agents`, `~/.config`, `~/.local`, `~/.cache`, `~/.docker`, `~/.colima`, `~/.lima`, `~/.ssh`, `~/.npm`, `~/.m2`, `~/.gradle`, `~/.composer`, `~/.cargo` | allow |
| Dotfiles directly in `~` (`~/.zshrc`, `~/.gitconfig`) | allow |
| `/dev/…` | allow |
| Inside the dev root, valid layout | allow |
| Inside the dev root, a file directly in `~/Development` | deny |
| Inside the dev root, a top-level folder that is not an owner you belong to, a host folder (contains a dot), `_local` or a dot folder — for example `kit-consulting-pr12` | deny |
| Backup-style names: `*.bak`, `*.orig`, `*.backup`, `*.old`, `*.rej`, `*~`, `*_old.*`, `*-copy.*`, `* copy.*`, `* (2).*` | deny |
| Anywhere else (Desktop, Documents, `~/notes.md`, …) | Claude: ask · Codex: deny |

"Owners you belong to" are your GitHub login and organisations (from `gh`, cached for a day) plus folders that
already exist in the dev root.

### Git

| Command | Decision |
|---|---|
| `git worktree add <path>` outside `~/Development/.worktrees` or a temp dir | deny → use `dev wt new <branch>` |
| `git clone <url> [dir]` to anything but the canonical path or a temp dir | deny → use `dev clone <url>` |
| `git clone <local path or unparseable url>` outside `_local` or temp | deny |
| `git push --force`, `-f`, combined short flags with `f`, `+refspec` | deny → `--force-with-lease` |
| `git push --force-with-lease` to `main`/`master` | deny |
| Third `git push` of the same branch within 60 minutes | deny unless prefixed `DEVKIT_LOCAL_CI_PASSED=1` |
| `git clean` with `-x` or `-X` | deny (deletes `.env`, local config, caches) |
| `git reset --hard` with uncommitted changes to tracked files | deny |
| `git commit`, `tag`, `merge`, `notes` whose message (inline or `-F` file) contains AI attribution | deny |
| `git init <dir>` that breaks the layout | deny |

AI attribution means any of: `Co-Authored-By: Claude / Codex / ChatGPT / OpenAI / Anthropic`, `noreply@anthropic.com`,
`noreply@openai.com`, "Generated with Claude Code", "Generated with Codex", "Generated by Claude/Codex",
"🤖 Generated with" (case-insensitive).

### GitHub CLI

| Command | Decision |
|---|---|
| `gh repo clone <repo> [dir]` to anything but the canonical path or a temp dir | deny |
| `gh run rerun …` | deny unless prefixed `DEVKIT_FLAKY=1` |
| `gh pr …`, `gh issue …`, `gh release …`, `gh api …` containing AI attribution | deny |

### Files and folders from the shell

| Command | Decision |
|---|---|
| `rm -r` / `-R` / `-rf` / `--recursive` of `/`, `~`, the dev root, the handoff repo, `.worktrees`, `_local`, the devkit repo, `~/Library`, `~/Documents`, `~/Desktop`, `~/Downloads`, `~/Pictures`, `~/Movies`, `~/Music`, `~/Applications`, `~/.claude`, `~/.codex`, `~/.agents`, `~/.config`, `~/.ssh`, `~/.local` | deny |
| `rm -r` of any `.git` directory | deny |
| `rm -r *`, `./*`, `.` or `..` while in `~`, the dev root or a top-level folder of it | deny |
| `rm -r` of a whole top-level folder of the dev root | deny |
| `rm -r` of a git worktree | deny → `dev wt rm` |
| `rm -r` of a repository checkout | deny |
| `mkdir`, `touch`, and the destination of `cp`, `mv`, `rsync`, `ditto` that break the layout | deny |
| `cp`/`mv`/… to a backup-style file name inside the dev root | deny |

Removing `node_modules`, `dist` and other folders inside a repository is allowed.

## Example messages

```text
Raw `git worktree add ../repo-pr12` would create an unmanaged worktree at ~/Development/repo-pr12. Use
`dev wt new <branch>` (…), or your harness's own worktree tool. Only create a worktree when the user asked for one
or parallel work really needs it.

This would be push #3 of `feat/x` in the last hour, and every push runs CI again. Stop the push-and-see loop: read
the failing log (`gh run view --log-failed`), run what CI runs locally (`dev ci` shows the exact commands), fix,
and push once. If the full local suite has just passed in this session, prefix the push with
DEVKIT_LOCAL_CI_PASSED=1.

User policy: no AI attribution in commits, tags or PRs. Remove the “co-authored-by: claude” line (no
Co-Authored-By/Generated-with trailers) and retry.
```

## Fail-open design

- A command the tokenizer cannot parse (for example unbalanced quotes) is allowed; only the attribution check runs
  on its raw text.
- Any exception in the guard is logged to `~/.local/state/devkit/logs/hooks.log` and the call is allowed.
- Every deny and ask is logged there too, so you can review what was blocked.

The guard sees the command text, not the inner commands of `$( … )` substitutions or scripts the command runs.

## Escape hatch

Start the agent with the guard off for a session that genuinely needs it:

```bash
DEVKIT_GUARD=off claude        # or: DEVKIT_GUARD=off codex
```

The variable is read from the agent process's environment, so prefixing a single command inside a session has no
effect. Prefer fixing the rule (with a test) when a denial is a false positive.

## Testing

The rules are pure functions covered by `tests/test_devkit.py`:

```bash
cd ~/Development/ancongui/devkit
python3 -m unittest discover -s tests -v
/usr/bin/python3 -m unittest discover -s tests -v     # the macOS system Python (3.9)
```

To check a single decision by hand:

```bash
echo '{"tool_name":"Bash","tool_input":{"command":"git push --force"},"cwd":"'"$PWD"'"}' \
  | dev hook guard --agent claude
```
